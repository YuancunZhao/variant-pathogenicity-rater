# Release Readiness Review

## v0.2.0-alpha2 Readiness

Review date: 2026-05-25
Target release: v0.2.0-alpha2
Scope: internal alpha for controlled testing of CLI, MCP batch tools,
real-world annotation batch workflow, and safety-boundary preservation

### Summary

The current `develop` branch is ready for v0.2.0-alpha2 internal testing. The
review found the alpha2 scope present: CLI commands for single, batch,
annotated-batch, and environment checks; MCP tools for single, batch, and
annotated variants; strict top-level MCP schemas; annotation adapter to
normalization to transcript selection to batch rating workflow; per-record
provenance; and explicit failed-record preservation.

This readiness conclusion is limited to internal alpha testing. It is not a
clinical validation statement.

Release gate record:

- Test command: `.venv/bin/python -m pytest`
- Test result: 244 passed
- Blocking issues: no blocking issues
- Provider/network posture: offline default; no network used in release review
- Safety posture: human review required

### Blocking Issues

No blocking release issues were identified in source, documentation, CLI/MCP
smoke review, or final pytest review.

### Non-Blocking Issues

- `src/variant_pathogenicity_rater_mcp.egg-info/PKG-INFO` may remain stale until
  packaging metadata is regenerated by an install/build command.
- Real-world annotation quality depends on caller-supplied local annotation
  files, source versions, genome build, transcript fields, and provenance.
- The benchmark and real-data smoke datasets remain alpha-sized, not the larger
  v0.2.0 final targets.
- CLI `annotated-batch` is intentionally conservative and less configurable
  than the Python/MCP workflow; advanced use should go through MCP or Python
  arguments.

### CLI Review

- `vpr rate` runs the existing offline/mock-backed `rate_variant` workflow and
  supports JSON or Markdown stdout.
- `vpr batch` accepts JSON, JSONL, CSV/TSV, and VCF-like input and supports
  stdout or file output in JSON or JSONL.
- `vpr annotated-batch` accepts VEP, ANNOVAR, bcftools csq, and generic
  annotation input, records annotation safety limitations, then calls batch
  rating.
- `vpr check-env` reuses `scripts/check_env.py`.
- Invalid input handling is explicit: unreadable files return non-zero CLI
  errors, malformed records are preserved in `failed_records`, and partial
  batch failures can be made non-zero with `--no-continue-on-error`.

### MCP Review

- `rate_variant` validates one supported variant input shape before pipeline
  execution.
- `rate_variant_batch` validates records or textual batch input and uses strict
  top-level schemas.
- `rate_annotated_variants` validates annotated records or textual annotation
  input and preserves annotation conversion metadata.
- Unknown top-level fields are rejected with structured
  `SCHEMA_VALIDATION_ERROR`; designated mock/provider payload containers remain
  flexible by design.

### Real-World Workflow Review

- Annotation adapters parse VEP, ANNOVAR, bcftools csq, and generic records.
- Parsed annotation is converted to normalized batch inputs and transcript
  selection metadata before the existing batch rate path is called.
- Per-record output preserves annotation provenance, normalization identity,
  transcript-selection summary, review flags, and limitations.
- Malformed annotation rows and failed rate records are returned in
  `failed_records` and also appear in `results`; they are not silently dropped.

### Safety Boundary Review

- ACMG business logic and the classification combiner were not changed.
- The combiner remains conservative: candidate-only, neutral/conflicting, and
  `strength: none` evidence is not counted.
- Annotation, normalization, and transcript selection do not generate ACMG
  evidence.
- ClinVar and literature outputs remain candidate/review-note only and do not
  auto-apply PP5/BP6 or literature-derived strong criteria.
- Human review remains required on classifications, reports, batch records, and
  failed records.
- Batch summaries do not suppress per-record review flags, limitations, or
  failed-record details.

## v0.2.0-alpha1 Readiness

Review date: 2026-05-22
Target release: v0.2.0-alpha1
Scope: internal alpha for controlled testing of the v0.2.0 ingestion, annotation,
normalization, transcript-selection, batch, and safety framework

### Summary

The current `develop` branch is ready for v0.2.0-alpha1 internal testing. The
final pytest gate is green, and the review found the intended v0.2 alpha
features present: single-variant `rate_variant`, batch `rate_variant_batch`,
normalization, annotation adapters, transcript selection, ClinVar provider,
population provider, SpliceAI-style computational provider, literature
candidate-only framework, reports, benchmark tests, real-data smoke tests, MCP
smoke tests, and batch tests.

This readiness conclusion is limited to internal alpha testing. It is not a
clinical validation statement.

Release gate record:

- Test command: `.venv/bin/python -m pytest`
- Test result: 228 passed
- Blocking issues: no blocking issues
- Provider/network posture: offline default
- Safety posture: human review required

### Blocking Issues

No blocking release issues were identified in source, documentation, or final
pytest review.

### Non-Blocking Issues

- `src/variant_pathogenicity_rater_mcp.egg-info/PKG-INFO` may remain stale until
  packaging metadata is regenerated by an install/build command.
- Some internal source/provider version strings still describe component
  implementation versions rather than the release version.
- The v0.2.0 plan still lists some alpha1 work as milestone language; keep it as
  planning history, but rely on these release notes for alpha1 status.
- The benchmark and real-data smoke datasets remain alpha-sized, not the larger
  v0.2.0 final targets.

### Functional Review

- `rate_variant` orchestrates normalization, provider retrieval, population
  rules, computational evidence, PVS1, ClinVar review notes, literature review
  notes, classification combining, and report generation.
- `rate_variant_batch` parses JSON, JSONL, CSV/TSV, and minimal VCF-like input,
  calls `rate_variant` independently per record, and preserves per-record
  failures.
- Normalization and HGVS/identity handling preserve unresolved fields and
  warnings instead of making unsafe mapping assumptions.
- Annotation adapters and transcript selection produce descriptive review
  context only.
- ClinVar and literature providers emit candidate/review-note evidence.
- Population and SpliceAI-style computational providers keep conservative
  limitations and review flags visible.
- Reports preserve human-review-required language and candidate evidence
  separation.

### Safety Boundary Review

- Human review remains required on classifications and reports.
- Candidate evidence is excluded from classification by `candidate_only`,
  `evidence_status: candidate`, or `strength: none`.
- ClinVar outputs remain candidate-only and do not auto-apply PP5/BP6.
- Literature outputs remain candidate-only and do not auto-apply PS3, BS3, PS2,
  PM6, PP1, PS4, or PP4.
- SpliceAI-style predictions support only computational PP3/BP4 and cannot
  trigger PS3, BS3, or PVS1.
- Annotation, normalization, and transcript selection do not generate
  `EvidenceItem` records for ACMG application.
- Batch mode records malformed, unsupported, and failed records explicitly.

Review date: 2026-05-22
Target release: v0.1.0
Scope: internal testing beta for the SNV/small-indel ACMG prototype

## Summary

The current project is ready for an internal v0.1.0 test release. The full
pytest suite passed with 178 passed tests in the target environment. The
implementation is offline-first by default, exposes the intended MCP tools, has
a working `rate_variant` pipeline, and documents the key safety boundaries for
candidate evidence and human review.

This readiness conclusion is limited to internal prototype testing. It is not a
clinical validation statement.

Release gate record:

- Test result: 178 passed
- Blocking issues: no blocking issues
- Provider/network posture: offline default
- Safety posture: human review required

## Blocking Issues

No blocking release issues were found in the reviewed source and documentation.

## Non-Blocking Issues

- README now includes a clearer fresh-install path, but internal users should
  still know how to enable a local Codex Plugin from this repository in their
  own Codex environment.
- MCP tool schemas are intentionally permissive in several places
  (`additionalProperties: true`) to preserve prototype flexibility. This is
  acceptable for v0.1.0, but stricter schemas should be considered before wider
  release.
- Provider docs describe local-file contracts, but supplied production-grade
  snapshot validation and source-version governance are outside v0.1.0 scope.

## Installation And Run

Status: ready for internal testing.

- `README.md` documents creating `.venv`, installing with
  `.venv/bin/python -m pip install -e ".[dev]"`, running tests, and checking the
  environment.
- MCP server startup is documented as
  `.venv/bin/python mcp-server/server.py`.
- `plugin.toml` points Codex Plugin execution at the same MCP server command
  over stdio.

## Core Functionality

Status: ready for internal testing.

- `rate_variant` orchestrates normalization, configured provider retrieval,
  population rules, computational rules, PVS1, ClinVar review notes, literature
  review notes, classification combining, and report generation.
- `normalize_variant` supports HGVS-like and VCF-like phase-1 inputs with
  unresolved-field warnings.
- ClinVar mock/local-file/online-gated provider behavior is configurable.
- Population mock/local-file provider behavior is configurable.
- SpliceAI-style local computational input is configurable through
  computational `local_file` mode.
- Report generation supports structured report output and markdown/plain/json
  rendering paths.

## Safety Boundary Review

Status: ready for internal testing.

- Human review is required on conclusions and reports.
- ClinVar assertions are candidate/review-note only and do not auto-apply
  PP5/BP6.
- PM2 is downgraded to supporting strength in this prototype.
- Provider misses explicitly avoid treating "no record found" as population
  absence.
- SpliceAI does not trigger PS3, BS3, or PVS1.
- Literature-derived strong evidence hints are candidate-only and not applied.

## Configuration Review

Status: ready for internal testing.

- Data source defaults are documented in README and implemented in
  `src/variant_pathogenicity_rater/config/data_sources.yaml`.
- Environment-variable overrides are documented in README and provider docs.
- Offline `mock` mode is the default.
- Online ClinVar requires explicit `mode=online` or `future_online` plus
  `online_enabled=true`.

## Test And Smoke Review

Status: ready for internal testing.

- Final local pytest gate recorded for v0.1.0: 178 passed.

- `docs/BENCHMARK.md` documents the curated benchmark suite.
- `docs/REAL_DATA_SMOKE.md` documents the real-data smoke suite.
- `scripts/check_env.py` reports Python, package, pytest, project, and MCP
  import status.
- `scripts/test.sh` runs pytest through `.venv/bin/python`.

## MCP And Plugin Review

Status: ready for internal testing.

- `plugin.toml` exists and declares plugin, server, MCP, and tool-discovery
  configuration.
- MCP tools are documented in `docs/MCP_TOOLS.md`.
- Tool errors use structured `McpToolError` fields: `code`, `message`,
  `details`, and `recoverable`.
- Pipeline step failures are returned as structured limitations so the pipeline
  can continue conservatively where possible.
